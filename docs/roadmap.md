# План разработки

Каждая строка — отдельное изменение со своей проверкой. Рабочий код, тест и инструкция попадают в GitHub вместе. Фактические адреса, ключи, пароли и отчёты устройства хранятся локально. Состояние проверки на B5 записываем в журнал с датой, командой и результатом.

**Состояние на 20 ноября 2026 г.** На B5 проверены шаги 01–10. [Релиз шага 11](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step11-20261120-1331-r6) установлен и прошёл smoke-проверки на устройстве: HTTPS health, отказ HTTP и неверного пароля, неавторизованная сессия и очистка cookie при выходе. Успешный вход с действующей учётной записью и отзыв её действительного сеанса на B5 отдельно не проверялись; полный позитивный сценарий покрыт CI. Служба остаётся привязана к loopback, SSH — на отдельном Wi-Fi-интерфейсе. Чистая переустановка Debian с развёртыванием двумя командами пока не проводилась. Подробности устройства и адреса хранятся только в локальном журнале.

**Решение для будущей установки.** Начальная LAN-подсеть `192.168.10.0/24`, IP маршрутизатора `192.168.10.1`, DHCP-пул по умолчанию `192.168.10.100–192.168.10.200`. Это начальные значения настроек, а не постоянные значения в правилах firewall или шаблонах DNS. Страница Network/LAN должна позволять изменить адрес маршрутизатора, префикс и DHCP-пул. Перед сохранением проверять диапазон, пересечение с WAN и сетью управления. Перед применением показать новый адрес интерфейса, подготовить независимый откат и пересчитать связанные настройки DHCP, DNS и firewall. Действующую конфигурацию устройства изменим после появления и проверки этой функции.

**Начальное назначение портов B5-2840.** `enp1s0` — WAN, `enp2s0` — LAN. Пользователь подтвердил это назначение, и наличие линка на каждом интерфейсе проверено по очереди. Мастер должен хранить роли портов как изменяемую настройку и проверять их перед применением сети.

**Шаг 04 проверен на B5.** Первый Go API собран для linux/amd64, ответил на локальный `GET /healthz` кодом 200 и JSON-статусом `ok`. Повторный запуск на занятом порту завершился с ошибкой и объяснением в журнале. После остановки процесса порт освободился.

**Шаг 05 проверен на B5.** Скрипт собрал архив версии `0.1.0` для linux/amd64 и файл SHA-256. Контрольная сумма совпала, внутри есть `VERSION` и исполняемый `router-api`. Запущенный из архива API ответил на локальный запрос. GitHub Actions прикладывает пакет к успешному прогону.

**Шаг 06 проверен на B5.** [Выпуск `v0.1.0-step06-20261119-2251-r1`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step06-20261119-2251-r1) создан ручным workflow из основного коммита. `install.sh --fetch-version latest` и запрос точной версии скачали архив, подтвердили SHA-256 и номер версии внутри. Неверная метка отвергнута. Контрольная сумма обнаружила подменённое содержимое архива до распаковки.

**Шаг 07 проверен на B5.** [Выпуск `v0.1.0-step07-20261119-2317-r2`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step07-20261119-2317-r2) установлен двумя командами из README. Служба `debian-router-api` включена, активна и отвечает по локальному адресу. Проверка в новом SSH-сеансе после закрытия сеанса установки прошла. Чистая переустановка Debian отдельно не проводилась.

**Шаг 08 проверен на B5 для существующего состояния.** Повторная установка `step07` сохранила PID и бинарник. [Выпуск `v0.1.0-step08-20261119-2338-r3`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step08-20261119-2338-r3) применён через `install.sh`: служба запустилась с новой версией, прежний каталог и бинарник сохранены. Повтор `step08` сохранил PID, активной осталась одна служба. Ветка отката при ошибке запуска написана, но на B5 ещё не испытана.

**Шаг 09 проверен на B5.** [Выпуск `v0.1.0-step09-20261119-2358-r4`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step09-20261119-2358-r4) установлен через две команды из README. Служба создала SQLite в постоянном каталоге systemd с ограниченным доступом. После записи тестовой настройки повторная установка сохранила PID и значение. Перезапуск службы повторно применил миграции: тестовая запись сохранилась, версия схемы осталась `1` в единственной строке. Тестовая настройка удалена.

**Шаг 10 проверен на B5.** [Выпуск `v0.1.0-step10-20261120-0456-r5`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step10-20261120-0456-r5) проверен по SHA-256 и установлен пользователем в собственном терминале. Случайный первичный пароль показан только там; в SQLite хранится хеш Argon2id и флаг обязательной смены. После первого локального входа пользователь сменил пароль, флаг стал `0`. Повторная установка сохранила PID и учётную запись; после перезапуска службы данные и ответ API сохранились. Локальный сброс пароля реализован и проверен тестом, но на действующей учётной записи B5 не запускался, чтобы не менять выбранный пароль. На шаге 11 реализованы HTTPS и сеансы; пароль по HTTP не передаётся.

**Шаг 11 установлен и прошёл smoke-проверку на B5.** [Релиз `v0.1.0-step11-20261120-1331-r6`](https://github.com/ASSever/debian-router-b5-2840/releases/tag/v0.1.0-step11-20261120-1331-r6) остаётся latest и указывает на основной коммит `732351abc499e471171598d20201c4ba823635df`. Перед установкой архив прошёл проверку SHA-256. На B5 служба active/enabled, схема SQLite — версия 2, listener — `127.0.0.1:8081`; проверенный сертификатом HTTPS `GET /healthz` ответил 200. Вход по HTTP отклонён (400), неверный пароль по HTTPS получил 401, неавторизованный статус сессии — 401, выход — 204 с очисткой cookie. [Workflow публикации](https://github.com/ASSever/debian-router-b5-2840/actions/runs/44719854215) прошёл тесты, сборку linux/amd64-пакета, проверку SHA-256 и структуры архива; тесты CI покрывают полный успешный вход, административные операции и отзыв действительной сессии. Позитивный сценарий с действующей учётной записью на B5 не выполнялся, чтобы не запрашивать пароль администратора.

**Шаг 12 в работе.** Добавлена React-страница состояния, которая проверяет `/healthz` и показывает потерю связи. Локальные frontend-проверки проходят; CI, выпуск и установка на B5 ещё ожидаются.

## Основа и установка

| Шаг | Изменение | Как принять |
|---|---|---|
| 01 | Единый файл запуска с обследованием Debian | Две команды из README дают отчёт. Неподдерживаемая ОС возвращает код 3. |
| 02 | Паспорт конкретного B5 | На B5 записаны CPU, RAM, диск, оба Ethernet-порта, адрес Wi-Fi, служба SSH и обратный маршрут к клиенту. Неподтверждённые данные отмечены. |
| 03 | Карта разъёмов WAN/LAN | Выбранные пользователем `enp1s0` для WAN и `enp2s0` для LAN проверены по смене link. Wi-Fi управления сохраняет связь. |
| 04 | Сборка первого Go API | Бинарник linux/amd64 отвечает на локальный запрос состояния, ошибка запуска видна в журнале. |
| 05 | Версионный пакет | Чистая сборка выпускает архив эксплуатационных файлов и контрольную сумму. |
| 06 | Получение релиза через установщик | Установщик скачивает выбранную версию, проверяет целостность, отвергает испорченный архив до установки. |
| 07 | Первая systemd-служба | Две команды ставят API на чистый Debian. API работает после выхода из SSH. |
| 08 | Повтор установки | Второй запуск сохраняет настройки и оставляет один экземпляр службы. |
| 09 | SQLite и миграции | Новая база открывается, повтор миграции сохраняет тестовую запись. |
| 10 | Локальный администратор | Индивидуальный пароль задаётся при установке, хранится хеш, первый вход требует смены пароля. |
| 11 | HTTPS и сеансы | На B5 проверены TLS health, отказ HTTP и неверного пароля, неавторизованная сессия и очистка cookie при выходе; CI проверяет успешный вход, административные операции и отзыв действительной сессии. |
| 12 | Каркас React UI | Англоязычная адаптивная страница показывает реальное состояние API и ошибку потери связи. |
| 13 | Привилегированный агент | Unix-сокет принимает разрешённый запрос и отклоняет неизвестные операции и постороннего пользователя. |
