# План разработки

Статус в таблице отражает этап приёмки. `planned` — реализация ещё не объединена в `main`. `b5-pending` — реализация объединена, выпуск или приёмка на B5 ещё предстоят. `verified` — приёмка на B5 подтверждена и записана. Навык `roadmap-step` выбирает первый шаг со статусом, отличным от `verified`.

Каждая строка — отдельное изменение со своей проверкой. Рабочий код, тест и инструкция попадают в GitHub вместе. Каждый завершённый шаг выпускается новым versioned GitHub Release, устанавливается на B5 и проверяется там; результат фиксируется в локальном setup log. Фактические адреса, ключи, пароли и отчёты устройства хранятся локально. Состояние проверки на B5 записываем в журнал с датой, командой и результатом.

**Решение для будущей установки.** Начальная LAN-подсеть `192.168.10.0/24`, IP маршрутизатора `192.168.10.1`, DHCP-пул по умолчанию `192.168.10.100–192.168.10.200`. Это начальные значения настроек, а не постоянные значения в правилах firewall или шаблонах DNS. Страница Network/LAN должна позволять изменить адрес маршрутизатора, префикс и DHCP-пул. Перед сохранением проверять диапазон, пересечение с WAN и сетью управления. Перед применением показать новый адрес интерфейса, подготовить независимый откат и пересчитать связанные настройки DHCP, DNS и firewall. Изменение действующей LAN выполняется в панели Network/LAN с подтверждением на новом адресе.

**Начальное назначение портов B5-2840.** `enp1s0` — WAN, `enp2s0` — LAN. Пользователь подтвердил это назначение, и наличие линка на каждом интерфейсе проверено по очереди. Мастер должен хранить роли портов как изменяемую настройку и проверять их перед применением сети.
