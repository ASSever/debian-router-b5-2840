# Независимый мониторинг

`debian-router-monitor.service` запускается при первой установке. Служба работает от отдельного динамического пользователя и продолжает проверять цели при остановке API. Состояние включения службы и история сохраняются при повторной установке. Обновление с выпуска без мониторинга создаёт отдельную базу, а возврат к такому выпуску останавливает монитор и сохраняет базу.

По умолчанию служба разрешает `github.com` и проверяет TCP-порт 443, а также проверяет локальный порт sing-box `127.0.0.1:11080`. Проверки используют маршруты самого роутера. Успешная проверка означает установленное TCP-соединение. Проверка порта sing-box измеряет доступность слушателя.

## Настройка целей

Разместите JSON в `/etc/debian-router-b5-2840/monitor.json`. Службе нужен доступ на чтение. Цели задаются уникальными именами и адресами вида `host:port`; для IPv6 используйте `[address]:port`. Допускается от 1 до 16 целей. Необязательный `dns_server` задаёт конкретный DNS-сервер в формате IP и порта. Без этого поля используется системная настройка DNS.

```json
{
  "interval_seconds": 60,
  "timeout_seconds": 5,
  "targets": [
    {"name": "internet", "address": "github.com:443"},
    {"name": "sing-box-listener", "address": "127.0.0.1:11080"}
  ]
}
```

Отсчёт интервала начинается после завершения очередного цикла. DNS и TCP получают отдельный тайм-аут. После редактирования проверьте конфигурацию перед перезапуском.

```sh
monitor=/opt/debian-router-b5-2840/current/router-monitor
sudo "$monitor" check-config
sudo systemctl restart debian-router-monitor.service
systemctl status debian-router-monitor.service
```

## История

```sh
sudo /opt/debian-router-b5-2840/current/router-monitor -limit 20 history
```

Команда читает последние записи из отдельной SQLite-базы `/var/lib/debian-router-monitor/monitor.db`. Запись содержит имя цели, время проверки UTC, этапы DNS и TCP и длительность в миллисекундах. Во время записи сохраняются результаты за последние семь дней в пределах 25 000 строк.

| Результат | Что произошло |
|---|---|
| `ok` | TCP-соединение установлено. Для цели с IP-адресом DNS отмечен как `not_required`. |
| `dns_failed` | Имя не разрешилось или DNS не ответил вовремя. TCP-проверка имеет статус `skipped`. |
| `transport_failed` | Адрес известен. TCP-подключение к полученным адресам не удалось за отведённое время. |

На приёмочном стенде одновременно проверяются цель по имени и контрольный IP. Сначала обе цели должны быть доступны. При остановке DNS контрольное TCP-соединение должно оставаться доступным. Затем DNS восстанавливается, а TCP-слушатель именованной цели отключается. Статусы и их порядок сверяются в истории после перезапуска монитора.
