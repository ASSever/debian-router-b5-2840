# Автоматическое переключение Zapret и Proxy

Установщик добавляет `debian-router-failover.service` в выключенном состоянии. Для включения задайте одну HTTPS-цель с выделенным IPv4-адресом. Служба управляет новыми IPv4 TCP-соединениями из выбранного LAN к этому адресу на порту 443. Для адреса, общего с другими доменами, такой режим применять нельзя.

Основная HTTPS-проверка выполняется с привязкой к выбранному WAN. Только её сокеты получают метку, по которой Zapret направляет пакеты в свою очередь NFQUEUE. Для резервной проверки служба устанавливает HTTP CONNECT к имени цели через локальный sing-box. Настройте действующий [профиль Proxy](proxy-routing.md), чтобы это имя шло через выбранный удалённый сервер. Служба использует текущий профиль sing-box, в том числе его правила и ограничения.

Две подряд неудачные проверки основного пути при работающем Proxy переключают новые соединения. Три подряд успешные проверки основного пути возвращают Zapret. Если обе проверки неудачны, сохраняется текущий режим. Уже открытые соединения сохраняют выбранный при открытии маршрут. Причину переключения можно посмотреть в журнале systemd. При перезапуске служба начинает с Zapret и снова проверяет оба пути.

## Настройка

Создайте `/etc/debian-router-b5-2840/failover.json`. Значения ниже приведены как пример. Укажите фактический LAN, используемый Zapret WAN, адрес маршрутизатора в LAN, выделенный адрес цели и URL с доверенным сертификатом. Дополнительное поле `ca_file` позволяет указать отдельный PEM-файл доверия для стенда.

```json
{
  "lan_interface": "enp2s0",
  "wan_interface": "enp1s0",
  "lan_prefix": "192.168.10.0/24",
  "lan_address": "192.168.10.1",
  "target_ip": "198.51.100.20",
  "probe_url": "https://canary.example.org/healthz",
  "interval_seconds": 5
}
```

Служба проверяет очереди Zapret на совпадающей паре интерфейсов. HTTP-код от 200 до 299 означает успешную HTTPS-пробу. Проверка использует системное доверие TLS и не следует перенаправлениям. Отсчёт интервала начинается после завершения обеих проб.

```sh
sudo /opt/debian-router-b5-2840/current/router-failover check-config
sudo systemctl enable --now debian-router-failover.service
sudo journalctl -u debian-router-failover.service -n 20
sudo nft list table ip b5_failover
```

Для остановки выполните `sudo systemctl disable --now debian-router-failover.service`. Служба удаляет свою таблицу nftables. UDP, IPv6 и остальные назначения следуют действующим правилам роутера.
