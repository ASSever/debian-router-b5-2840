# История измерений и Dashboard

Откройте **Dashboard** в веб-интерфейсе и войдите паролем локального администратора. При первом входе интерфейс предложит сменить начальный пароль, затем войти повторно. Данные доступны за действующим сеансом через `GET /api/dashboard`. Интерфейс обновляет открытый Dashboard каждые 30 секунд.

API сохраняет один снимок примерно каждые 30 секунд в отдельной SQLite-базе `metrics.db` в каталоге состояния службы `debian-router-api`. Сбор начинается при запуске API. Хранятся записи за 24 часа, максимум 2880 записей. Dashboard запрашивает до 60 последних сохранённых снимков в хронологическом порядке. Существующие базы настроек и Connectivity Monitor используют свои схемы.

- Графики интерфейсов показывают RX и TX. Графики клиента показывают download и upload по IP-адресу LAN. Скорость в B/s вычисляется из соседних показаний [счётчиков](traffic.md) и фактического интервала. Первый снимок, смена поколения клиентских счётчиков, уменьшение счётчика и разрыв больше 60 секунд оставляют пропуск. Значение 0 B/s отображается как измеренный ноль. Снимок старше 90 секунд помечается как устаревший.
- Состояния служб берутся из systemd. Состояния WAN и LAN и скорость линка берутся из ядра. Шлюз и DNS WAN читаются через агент, как и состояние правил firewall. Число LAN IP показывает адреса, присутствующие в клиентских счётчиках.
- CPU — доля активного времени по `/proc/stat` за интервал. RAM — `MemTotal − MemAvailable`. Хранилище — занятое и полное пространство файловой системы каталога состояния, без добавления зарезервированных блоков к занятому месту. Температура CPU доступна при наличии `x86_pkg_temp`, uptime берётся из `/proc/uptime`.

При откате к r42 база `metrics.db` остаётся на диске. Сбор возобновляется при установке версии с Dashboard.
