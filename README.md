# Debian Router B5-2840

Домашний маршрутизатор для Debian 13 amd64. Сейчас доступны установщик, локальный Go API, постоянная база SQLite и локальная учётная запись администратора. Следующие этапы перечислены в [плане разработки](docs/roadmap.md).

Начальная LAN-подсеть проекта — `192.168.10.0/24`, адрес маршрутизатора — `192.168.10.1`. Адрес и DHCP-пул будут редактироваться в настройках устройства. До применения новой сети интерфейс проверяет пересечение с WAN и сетью управления, показывает новый адрес и обеспечивает автоматический откат при потере доступа. Эти настройки пока не применяются установщиком.

Для B5-2840 выбрано начальное назначение Ethernet-интерфейсов: `enp1s0` — WAN для кабеля провайдера, `enp2s0` — LAN для коммутатора и домашних устройств. Мастер настройки должен показывать реальные интерфейсы и позволять изменить назначение с безопасным откатом.

## Запуск на чистом Debian

**[TARGET B5-2840]** Из каталога, в который пользователь может записывать файлы, скачайте точку входа и запустите её. Для загрузки нужны доступ к GitHub по HTTPS и системные корневые сертификаты. Загрузчик входит в пакет Debian `apt`.

```sh
/usr/lib/apt/apt-helper download-file https://raw.githubusercontent.com/ASSever/debian-router-b5-2840/main/install.sh install.sh
sudo sh ./install.sh
```

Команды скачивают последнюю проверенную версию API с GitHub Releases и устанавливают systemd-службу `debian-router-api`. На чистом Debian с входом под `root` во второй команде достаточно `sh ./install.sh`. Запускайте установку в интерактивном терминале: при первом запуске она покажет случайный пароль для `admin` **один раз**. Сохраните его в менеджере паролей. Установщик передаёт вывод напрямую терминалу, не записывает пароль в файл, журнал, аргументы процесса или переменные окружения. В SQLite хранится только хеш Argon2id и признак обязательной смены пароля. Повтор установки пароль не показывает. Если терминала нет и администратора ещё нет, установка остановится до переключения работающей версии.

Служба слушает только `127.0.0.1:8081` по HTTPS. При первом запуске она создаёт постоянный самоподписанный сертификат для `localhost` и `127.0.0.1`; браузер предупредит о доверии к сертификату. Чтобы передать публичный сертификат на рабочий компьютер, выполните команду там же, где открыт SSH-клиент; частный ключ не экспортируется:

```sh
ssh user@ROUTER 'sudo systemd-run --pipe --quiet --collect -p DynamicUser=yes -p StateDirectory=debian-router-b5-2840 -p StateDirectoryMode=0700 /opt/debian-router-b5-2840/current/router-api tls-certificate' > router-api.crt
```

Добавьте `router-api.crt` в доверенные сертификаты клиента. Для доступа с рабочего компьютера сначала откройте SSH-туннель `ssh -L 8081:127.0.0.1:8081 user@ROUTER`, затем используйте `https://127.0.0.1:8081`. Для сертификата своей инфраструктуры можно настроить systemd credentials:

```ini
[Service]
LoadCredential=router-tls-cert:/etc/debian-router/router.crt
LoadCredential=router-tls-key:/etc/debian-router/router.key
Environment=ROUTER_TLS_CERT_FILE=%d/router-tls-cert
Environment=ROUTER_TLS_KEY_FILE=%d/router-tls-key
```

Сохраните этот блок в `sudo systemctl edit debian-router-api`, положите ключ в `/etc/debian-router/router.key` с правами `0600`, затем выполните `sudo systemctl restart debian-router-api`. Сертификат должен содержать имя или IP-адрес, по которому клиент открывает маршрутизатор. Если переменные не заданы, частный ключ локального сертификата хранится в закрытом каталоге состояния службы.

Веб-вход и сеансы API доступны по HTTPS: `POST /api/auth/login` с JSON `{ "password": "…" }`, `GET /api/auth/session` для статуса, `PUT /api/auth/password` для смены пароля, `DELETE /api/auth/session` для выхода. Для изменений требуется заголовок same-origin `Origin`. Сеанс хранится в `HttpOnly`, `Secure`, `SameSite=Strict` cookie; в SQLite записывается только хеш токена. Смена или локальный сброс пароля отзывают все сеансы. Обязательную смену первичного пароля можно пройти через API или локально на консоли B5:

```sh
sudo systemd-run --pipe --quiet --collect -p DynamicUser=yes -p StateDirectory=debian-router-b5-2840 -p StateDirectoryMode=0700 /opt/debian-router-b5-2840/current/router-api admin-login
```

Команда запросит выданный пароль без отображения ввода и затем новый пароль длиной не менее 12 байт. Если первоначальный пароль потерян, с локальной консоли или через доверенный SSH-сеанс выполните ту же команду с `admin-reset` вместо `admin-login`: новый случайный пароль будет показан один раз, следующий вход снова потребует смены. Эти команды требуют `sudo` и работают с тем же постоянным каталогом данных, что и служба.

Режим `sh ./install.sh --check` выполняет обследование от обычного пользователя. Отчёт содержит локальные адреса, MAC и маршруты, храните его на своей машине. Код выхода `2` означает ошибку параметров, `3` — несовместимую платформу. Отдельные необязательные утилиты или службы могут быть недоступны, это видно в выводе.

Сценарий показывает оборудование, диски, типы интерфейсов и состояние линии, адреса, маршруты, путь текущего SSH-сеанса, службы, данные локального кэша APT и синхронизацию времени. Для строки о пути управления запустите его в SSH-сеансе. Значение `carrier=1` означает, что драйвер видит соединение. `unknown` означает, что драйвер не сообщил значение.

## Первый Go API

Исходники находятся в `backend/`. После установки Go 1.24 или новее разработчик может выполнить `cd backend`, затем `go test ./...` и `go build -o router-api ./cmd/router-api`. Для локального запуска сначала выполните `./router-api admin-init` в интерактивном терминале, затем `./router-api`: без созданного администратора сервер не запускается. Бинарник слушает только `127.0.0.1:8081` по HTTPS. Запрос `GET https://127.0.0.1:8081/healthz` отвечает `{"status":"ok"}`; самоподписанный сертификат нужно добавить в доверенные сертификаты клиента. Ошибки открытия базы или порта выводятся в stderr и завершают процесс с ненулевым кодом. Установщик создаёт службу `debian-router-api` для постоянного запуска. На B5 база SQLite хранится в постоянном каталоге systemd `/var/lib/debian-router-b5-2840/router.db` и сохраняется при повторной установке и смене версии. При локальном запуске без systemd база создаётся в текущем каталоге. Миграции применяются при старте службы; если база создана более новой версией приложения, старая версия отказывается её открывать.

## Версионный пакет

**[DEV HOST или TARGET B5-2840]** В корне проекта с Go 1.24 или новее выполните `sh scripts/package.sh 0.1.0`. Результат находится в `dist/0.1.0/`: архив `debian-router-b5-2840-0.1.0.tar.gz` и файл SHA-256 рядом. Архив содержит `VERSION` и бинарник `router-api` для linux/amd64. Проверка выполняется командой `cd dist/0.1.0 && sha256sum -c debian-router-b5-2840-0.1.0.tar.gz.sha256`. Повторная сборка той же версии требует удалить или перенести ранее созданный каталог версии.

Для публичного выпуска запускается ручной workflow **Publish release**. Его метка имеет формат `v0.1.0-step11-YYYYMMDD-HHMM-rN`, где время указано по Москве, `step11` — номер завершённого пункта, `N` — номер запуска workflow. Проверенный пакет и файл SHA-256 прикладываются к GitHub Release. Этот способ сохраняет версию, пункт и время до минуты в имени каждого выпуска.

**[TARGET B5-2840]** Команда `sh ./install.sh --fetch-version latest` скачивает последний пакет, проверяет SHA-256 и структуру архива от обычного пользователя. Для установки определённого выпуска под `root` используйте `sh ./install.sh --install-version 0.1.0-step11-YYYYMMDD-HHMM-rN`, подставив реальную метку без начальной `v`. Режим без аргументов устанавливает последний выпуск. Повтор той же версии сохраняет работающий процесс. При переходе на новую версию установщик сохраняет прежний бинарник и возвращает его, если служба не запустится. Обследование доступно через `--check`.

Все последующие версии сохранят схему «скачать и запустить». Релиз с установкой служб должен пройти проверку на свежем Debian и повторную установку с сохранением настроек.

## Проверки разработчика

**[DEV HOST]** Из корня репозитория в Git Bash или POSIX-оболочке запустите `sh tests/bootstrap.sh`. GitHub Actions проверяет поддерживаемую систему в контейнере Debian 13 amd64 под непривилегированным пользователем и отказ на другой ОС. Проверка физических портов и действующего SSH-пути проводится отдельно на B5.
