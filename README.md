# Debian Router B5-2840

Домашний маршрутизатор для Debian 13 amd64. Сейчас доступны установщик, HTTPS API, React-страница управления, чтение WAN DHCP, временное применение WAN Static и PPPoE с независимым откатом, постоянная база SQLite и локальная учётная запись администратора. Следующие этапы перечислены в [плане разработки](docs/roadmap.md).

Начальная LAN-подсеть проекта — `192.168.10.0/24`, адрес маршрутизатора — `192.168.10.1`. Адрес и DHCP-пул можно менять в панели **Network / LAN**. Перед применением роутер проверяет пересечение с WAN и сетью управления. Для сохранения подтвердите настройки по новому адресу. Если подтверждение не получено, systemd вернёт предыдущий профиль. Установщик оставляет существующую конфигурацию LAN до применения через панель.

Для B5-2840 выбрано начальное назначение Ethernet-интерфейсов: `enp1s0` — WAN для кабеля провайдера, `enp2s0` — LAN для коммутатора и домашних устройств. Мастер настройки должен показывать реальные интерфейсы и позволять изменить назначение с безопасным откатом.

## Запуск на чистом Debian

**[TARGET B5-2840]** Из каталога, в который пользователь может записывать файлы, скачайте точку входа и запустите её. Для загрузки нужны доступ к GitHub по HTTPS и системные корневые сертификаты. Загрузчик входит в пакет Debian `apt`.

```sh
rm -f ./debian-router-install.sh && /usr/lib/apt/apt-helper download-file https://raw.githubusercontent.com/ASSever/debian-router-b5-2840/main/install.sh ./debian-router-install.sh
sudo sh ./debian-router-install.sh
```

Команды скачивают последний проверенный API и React UI с GitHub Releases. Первая команда удаляет прежнюю локальную копию установщика, чтобы повторная загрузка не продолжила старый файл. Начиная с шага 13, установщик также включает службу `debian-router-agent` с ограниченным Unix socket API. На чистом Debian с входом под `root` во второй команде достаточно `sh ./debian-router-install.sh`. Запускайте установку в интерактивном терминале: при первом запуске она покажет случайный пароль для `admin` **один раз**. Сохраните его в менеджере паролей. Установщик передаёт вывод напрямую терминалу, не записывает пароль в файл, журнал, аргументы процесса или переменные окружения. В SQLite хранится только хеш Argon2id и признак обязательной смены пароля. Повтор установки пароль не показывает. Если терминала нет и администратора ещё нет, установка остановится до переключения работающей версии.

Служба слушает только `127.0.0.1:8081` по HTTPS. При первом запуске она создаёт постоянный самоподписанный сертификат для `localhost` и `127.0.0.1`; браузер предупредит о доверии к сертификату. Чтобы передать публичный сертификат на рабочий компьютер, выполните команду там же, где открыт SSH-клиент; частный ключ не экспортируется:

```sh
ssh user@ROUTER 'sudo systemd-run --pipe --quiet --collect -p DynamicUser=yes -p StateDirectory=debian-router-b5-2840 -p StateDirectoryMode=0700 /opt/debian-router-b5-2840/current/router-api tls-certificate' > router-api.crt
```

Добавьте `router-api.crt` в доверенные сертификаты клиента. Для доступа с рабочего компьютера сначала откройте SSH-туннель `ssh -L 8081:127.0.0.1:8081 user@ROUTER`, затем используйте `https://127.0.0.1:8081`. Для сертификата своей инфраструктуры можно настроить systemd credentials:

```ini
[Service]
LoadCredential=router-tls-cert:/etc/debian-router/router.crt
LoadCredential=router-tls-key:/etc/debian-router/router.key
Environment=ROUTER_TLS_CERT_FILE=%d/router-tls-cert
Environment=ROUTER_TLS_KEY_FILE=%d/router-tls-key
```

Сохраните этот блок в `sudo systemctl edit debian-router-api`, положите ключ в `/etc/debian-router/router.key` с правами `0600`, затем выполните `sudo systemctl restart debian-router-api`. Сертификат должен содержать имя или IP-адрес, по которому клиент открывает маршрутизатор. Если переменные не заданы, частный ключ локального сертификата хранится в закрытом каталоге состояния службы.

## Веб-интерфейс

После открытия HTTPS-адреса в браузере страница показывает, отвечает ли API. Она периодически проверяет `/healthz`, сообщает об обрыве связи и продолжает проверки автоматически. Доступ с другого компьютера идёт через SSH-туннель; API и UI остаются привязаны только к `127.0.0.1:8081`.

Веб-вход и сеансы API доступны по HTTPS: `POST /api/auth/login` с JSON `{ "password": "…" }`, `GET /api/auth/session` для статуса, `PUT /api/auth/password` для смены пароля, `DELETE /api/auth/session` для выхода. Для изменений требуется заголовок same-origin `Origin`. Сеанс хранится в `HttpOnly`, `Secure`, `SameSite=Strict` cookie; в SQLite записывается только хеш токена. Смена или локальный сброс пароля отзывают все сеансы. Обязательную смену первичного пароля можно пройти через API или локально на консоли B5:

```sh
sudo systemd-run --pipe --quiet --collect -p DynamicUser=yes -p StateDirectory=debian-router-b5-2840 -p StateDirectoryMode=0700 /opt/debian-router-b5-2840/current/router-api admin-login
```

Команда запросит выданный пароль без отображения ввода и затем новый пароль длиной не менее 12 байт. Если первоначальный пароль потерян, с локальной консоли или через доверенный SSH-сеанс выполните ту же команду с `admin-reset` вместо `admin-login`: новый случайный пароль будет показан один раз, следующий вход снова потребует смены. Эти команды требуют `sudo` и работают с тем же постоянным каталогом данных, что и служба.

Панель **Static IPv4 settings** принимает статические адрес, шлюз и DNS для `enp1s0`. При наличии DHCP-аренды она использует её как начальное значение формы. Применение открывает 120-секундное окно: подтвердите настройки после проверки WAN или восстановите прежний профиль вручную; если ничего не выбирать, независимый systemd timer выполнит откат. Подробности и ограничения описаны в [docs/network-static.md](docs/network-static.md). Эта панель не меняет LAN.

Панель **PPPoE** настраивает логин и пароль провайдера с тем же 120-секундным откатом, показывает ошибку входа и позволяет переподключить сессию. Проверки B5 и текущее ограничение переключения режима описаны в [docs/network-pppoe.md](docs/network-pppoe.md).

В панели **DHCP WAN line settings** можно задать VLAN ID, исходящий PCP, MTU и MAC clone с тем же независимым откатом. Диапазоны и возврат к обычному DHCP описаны в [docs/network-wan-line.md](docs/network-wan-line.md).

Панель **Network / LAN** меняет подсеть IPv4 и DHCP-пул с проверкой пересечений и независимым откатом. Подготовка клиента и подтверждение по новому адресу описаны в [docs/network-lan.md](docs/network-lan.md).

## Привилегированный агент

`debian-router-agent.service` работает отдельно и принимает запросы только через `/run/debian-router-agent/agent.sock`. Сокет доступен выделенной системной группе `debian-router-agent`; API получает эту группу через systemd `Group=` при сохранении `DynamicUser=yes`. Агент сверяет первичный GID клиента по `SO_PEERCRED`. Разрешены только `status`, чтение сетевого статуса интерфейса и фиксированные операции транзакций Static WAN и PPPoE для `enp1s0`. Установщик ограничивает запись агента его каталогом состояния и `/etc/systemd/network`; неизвестные операции и запросы от других групп отклоняются. Агент не исполняет произвольные shell-команды. Неподтверждённая WAN-транзакция восстанавливается таймером или при следующем старте агента.

Режим `sh ./install.sh --check` выполняет обследование от обычного пользователя. Отчёт содержит локальные адреса, MAC и маршруты, храните его на своей машине. Код выхода `2` означает ошибку параметров, `3` — несовместимую платформу. Отдельные необязательные утилиты или службы могут быть недоступны, это видно в выводе.

Сценарий показывает оборудование, диски, типы интерфейсов и состояние линии, адреса, маршруты, путь текущего SSH-сеанса, службы, данные локального кэша APT и синхронизацию времени. Для строки о пути управления запустите его в SSH-сеансе. Значение `carrier=1` означает, что драйвер видит соединение. `unknown` означает, что драйвер не сообщил значение.

## Первый Go API

Исходники API и агента находятся в `backend/`, UI — в `frontend/`. Для UI нужен Node.js 22 или новее. Для локальной разработки сначала соберите UI:

```sh
cd frontend
npm ci
npm test
npm run typecheck
npm run lint
npm run format:check
npm run build
```

Для Go API и агента установите Go 1.24 или новее, затем из `backend/` выполните `go test ./...`, `go build -o router-api ./cmd/router-api` и `go build -o router-agent ./cmd/router-agent`. При локальном запуске API задайте `ROUTER_UI_DIR=../frontend/dist`, выполните `./router-api admin-init` в интерактивном терминале, затем `./router-api`: без созданного администратора сервер не запускается. Для локального агента задайте `ROUTER_AGENT_ALLOWED_GID` равным GID выделенной группы и запустите `./router-agent`; команда `./router-agent request status` отправит разрешённый запрос. API слушает только `127.0.0.1:8081` по HTTPS. Запрос `GET https://127.0.0.1:8081/healthz` отвечает `{"status":"ok"}`; самоподписанный сертификат нужно добавить в доверенные сертификаты клиента. Ошибки открытия базы или порта выводятся в stderr и завершают процесс с ненулевым кодом. Установщик задаёт `ROUTER_UI_DIR` и создаёт службы API и привилегированного агента. На B5 база SQLite хранится в постоянном каталоге systemd `/var/lib/debian-router-b5-2840/router.db` и сохраняется при повторной установке и смене версии. При локальном запуске без systemd база создаётся в текущем каталоге. Миграции применяются при старте службы; если база создана более новой версией приложения, старая версия отказывается её открывать.

## Версионный пакет

**[DEV HOST]** Сначала выполните `npm ci` и `npm run build` из `frontend/`. С Go 1.24 или новее затем из корня проекта выполните `sh scripts/package.sh 0.1.0`. Результат находится в `dist/0.1.0/`: архив `debian-router-b5-2840-0.1.0.tar.gz` и файл SHA-256 рядом. Архив содержит `VERSION`, бинарники `router-api` и `router-agent` для linux/amd64 и скомпилированные файлы UI. Проверка выполняется командой `cd dist/0.1.0 && sha256sum -c debian-router-b5-2840-0.1.0.tar.gz.sha256`. Повторная сборка той же версии требует удалить или перенести ранее созданный каталог версии.

Для каждого завершённого пункта roadmap запускается ручной workflow **Publish release** с номером этапа. Его метка имеет формат `v0.1.0-stepNN-YYYYMMDD-HHMM-rN`, где время указано по Москве, `NN` — номер этапа, `N` — номер запуска workflow. Workflow проверяет UI и Go API, собирает пакет и прикладывает архив с SHA-256 к GitHub Release как latest. После этого выпуск устанавливается и проверяется на B5.

**[TARGET B5-2840]** Команда `sh ./install.sh --fetch-version latest` скачивает последний пакет, проверяет SHA-256 и структуру архива от обычного пользователя. Для установки определённого выпуска под `root` используйте `sh ./install.sh --install-version 0.1.0-stepNN-YYYYMMDD-HHMM-rN`, подставив номер этапа и реальную метку без начальной `v`. Режим без аргументов устанавливает последний выпуск. Повтор той же версии сохраняет работающий процесс. При переходе на новую версию установщик сохраняет прежний бинарник и возвращает его, если служба не запустится. Обследование доступно через `--check`.

Все последующие версии сохранят схему «скачать и запустить». Релиз с установкой служб должен пройти проверку на свежем Debian и повторную установку с сохранением настроек.
